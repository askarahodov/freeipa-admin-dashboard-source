# User / Viewer guide

## Для кого

Для пользователя с ролью `viewer` или для любого сотрудника, которому нужно безопасно просматривать доступные данные без административных изменений.

## Что вы сможете сделать

Просматривать пользователей и группы FreeIPA, каталог процессов XYOps, операции и доступные результаты, а также понимать основные состояния ошибок и ограничений.

## Что разрешено Viewer

Встроенная роль `viewer` имеет permission `directory.read` и предназначена для чтения доступных данных. Изменение FreeIPA объектов, запуск процессов и административные настройки требуют дополнительных permissions и серверной проверки.

Канонический источник: [`../../reference/PERMISSIONS.md`](../../reference/PERMISSIONS.md).

## Просмотр пользователей FreeIPA

1. Откройте раздел пользователей / Directory.
2. Используйте доступный поиск и фильтры, если они показаны интерфейсом.
3. Откройте запись пользователя для просмотра доступных сведений.
4. Если результат пустой, сначала проверьте фильтры. Пустой список и недоступность FreeIPA — разные состояния.

Портал получает FreeIPA данные через серверную интеграцию. Браузеру не требуются и не должны передаваться FreeIPA credentials или session cookie.

## Просмотр групп FreeIPA

1. Откройте раздел групп.
2. Найдите нужную группу.
3. Просмотрите доступный состав группы или связанную информацию.
4. Если членство не загружается, ориентируйтесь на состояние интерфейса: отсутствие членов не следует автоматически считать ошибкой интеграции.

## Каталог процессов XYOps

1. Откройте Automation / Catalog.
2. Найдите процесс по доступному названию или категории.
3. Просмотрите его описание и доступные поля.
4. Viewer не должен считать наличие карточки процесса разрешением на запуск: запуск требует `xyops.run` и дополнительных server-side policy checks.

Каталог может дополнительно фильтроваться текущей visibility policy.

## Просмотр операций и результатов

1. Откройте Operations / Runs.
2. Найдите нужную операцию по доступным фильтрам.
3. Просмотрите её состояние и результат.
4. Если для операции доступны файлы результата, портал выдаёт только разрешённые result files через server-side boundary.

Не пытайтесь использовать внутренний URL XYOps напрямую: интеграционные credentials остаются на сервере.

## Approvals

Viewer может видеть approvals, доступные текущей сессии, но действие approve/reject требует отдельного permission `xyops.approve` и правил approval policy.

Не путайте наличие approval в списке с правом принять решение по нему.

## Если данные не появились

Проверьте, какое именно состояние показывает портал:

- **нет данных** — запрос успешен, но ничего не найдено;
- **forbidden / нет прав** — сервер отклонил доступ для вашей роли;
- **unavailable** — нужный источник сейчас недоступен;
- **degraded** — внешняя зависимость работает не полностью;
- **loading** — запрос ещё выполняется.

Не обновляйте страницу многократно, если интерфейс явно просит дождаться повторной попытки или показывает `Retry-After`.

## Когда обращаться к оператору или администратору

Обратитесь за помощью, если:

- вам требуется изменить пользователя или группу;
- нужно запустить процесс;
- нужно изменить настройки;
- сервер возвращает forbidden для задачи, которая по рабочему процессу должна быть вам доступна;
- FreeIPA или XYOps остаются unavailable/degraded длительное время;
- вы не можете войти в портал.

Передайте время, название задачи, безопасный error code и correlation ID, если они показаны. Не передавайте пароль, cookies, API keys, admin/encryption tokens или raw database.
