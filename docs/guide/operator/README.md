# Operator guide

## Для кого

Для пользователя с встроенной ролью `operator` или эквивалентным текущим набором permissions.

Текущий built-in `operator` имеет:

- `directory.read`;
- `freeipa.write`;
- `xyops.run`.

Он **не** получает автоматически `freeipa.delete`, `xyops.approve` или `settings.manage`.

Канонический permission contract: [`../../reference/PERMISSIONS.md`](../../reference/PERMISSIONS.md).

## Что вы сможете сделать

В рамках текущих server-side правил оператор может:

- просматривать FreeIPA users/groups;
- создавать и изменять обычные FreeIPA объекты;
- включать/отключать пользователей;
- менять membership;
- выполнять поддерживаемый password reset;
- запускать разрешённые XYOps processes;
- останавливать или безопасно повторять поддерживаемые runs;
- работать с доступными approval requests в пределах `xyops.run`, но не approve/reject без отдельного `xyops.approve`.

Каждая операция дополнительно проверяется сервером. Наличие кнопки в UI не является разрешением само по себе.

## Работа с пользователями FreeIPA

### Найти пользователя

1. Откройте раздел Users / Directory.
2. Используйте поиск и доступные фильтры.
3. Откройте нужного пользователя и проверьте, что выбрана правильная запись до изменения.

### Создать пользователя

1. Откройте действие создания пользователя.
2. Заполните обязательные поля.
3. Проверьте значения до отправки.
4. Выполните создание.
5. После успеха повторно найдите пользователя и убедитесь, что объект существует.

### Изменить пользователя

Оператор может выполнять поддерживаемые изменения через permission `freeipa.write`. Перед сохранением убедитесь, что редактируется нужный объект и изменение не является удалением.

### Enable / Disable

1. Найдите пользователя.
2. Проверьте текущее состояние.
3. Выполните enable или disable.
4. После результата обновите данные и убедитесь, что состояние изменилось.

Disable не означает удаление объекта.

### Password reset

Password reset относится к FreeIPA mutation и требует `freeipa.write`.

- не записывайте пароль в issue, chat, screenshot или log;
- не передавайте пароль через неподходящий канал;
- после reset проверьте только безопасный результат операции, а не содержимое секрета в логах.

### Удаление пользователя

Built-in `operator` не имеет `freeipa.delete`. Если требуется удалить пользователя или группу, передайте задачу администратору или роли с соответствующим permission.

Не пытайтесь обходить это через прямой API-вызов.

## Работа с группами FreeIPA

### Создать или изменить группу

Поддерживаемые ordinary group mutations используют `freeipa.write`.

1. Найдите существующую группу или откройте создание новой.
2. Проверьте имя и назначение группы.
3. Выполните изменение.
4. Повторно откройте группу и проверьте результат.

### Membership

Оператор может выполнять поддерживаемые membership operations через `freeipa.write`.

Перед изменением проверьте:

- правильную группу;
- правильного пользователя;
- направление действия — добавить или удалить membership.

После операции повторно загрузите состав группы.

Удаление самой группы требует отдельного `freeipa.delete`.

## Работа с XYOps

### Найти процесс

1. Откройте Automation / Catalog.
2. Найдите нужный Event или Workflow.
3. Прочитайте описание и проверьте параметры.
4. Убедитесь, что выбран именно тот process, который нужен для рабочей задачи.

XYOps остаётся владельцем определения процесса и исполнения. Портал не является второй scheduler/queue системой.

### Запустить процесс

1. Откройте нужный process.
2. Заполните разрешённые параметры.
3. Проверьте значения перед запуском.
4. Запустите process.
5. Перейдите к Operations / Runs и следите за состоянием.

Permission `xyops.run` не отменяет catalog visibility и approval policy. Опасная операция может потребовать согласование.

### Approvals

Built-in `operator` не имеет `xyops.approve`, поэтому approve/reject не входит в его базовые возможности.

Оператор с `xyops.run` может видеть доступные approval requests и выполнять действия, которые текущий approval contract разрешает requester/executor, например отмену допустимого запроса или execution после достаточного approval. Конкретное решение всегда проверяется сервером.

### Отмена run

Если текущий XYOps job поддерживает остановку и сервер разрешает действие:

1. откройте run;
2. проверьте, что он ещё активен;
3. выполните cancel/stop;
4. дождитесь подтверждённого итогового состояния.

Не считайте нажатие кнопки доказательством остановки — проверяйте состояние run.

### Rerun / safe replay

Повторный запуск разрешён только там, где сервер определяет run как replayable и текущий catalog/policy contract это допускает.

Не создавайте повторный run вручную только потому, что предыдущий запрос завершился timeout: сначала проверьте Operations, чтобы не получить duplicate execution.

## 409 Conflict

`409` обычно означает, что текущее состояние не позволяет выполнить запрос как обычную новую операцию: возможен conflict, stale state или несовместимое состояние ресурса.

Безопасный порядок:

1. обновите актуальное состояние;
2. проверьте, не была ли операция уже выполнена;
3. не повторяйте mutation вслепую;
4. если причина непонятна — передайте correlation ID администратору/поддержке.

## 429 Too Many Requests

`429` означает, что запросы временно ограничены.

Если ответ содержит `Retry-After`, дождитесь указанного интервала. Не запускайте несколько параллельных повторов и не пытайтесь обходить ограничение.

Для XYOps портал должен сохранять ownership внешнего rate limit/queue у XYOps и не создавать второй scheduler.

## FreeIPA или XYOps degraded

Если одна интеграция degraded/unavailable:

- не считайте весь портал остановленным;
- определите, какая именно dependency недоступна;
- не отключайте TLS или permission checks ради восстановления;
- используйте доступные diagnostics/status;
- повторяйте mutation только когда известно, что предыдущая не была выполнена.

При uncertain outcome сначала проверяйте фактическое состояние объекта/run.

## Когда нужен Administrator

Передайте задачу администратору, если требуется:

- удалить FreeIPA user/group (`freeipa.delete`);
- approve/reject approval (`xyops.approve`);
- изменить portal settings (`settings.manage`);
- управлять portal accounts/sessions;
- выполнять backup/restore/maintenance/recovery;
- разбирать длительный integration/security/storage incident.

## Что передать поддержке

Можно передать:

- время события;
- название действия;
- безопасный status/error code;
- correlation ID;
- идентификатор run/object, если он не содержит чувствительных данных и это разрешено процессом поддержки.

Не передавайте:

- пароль;
- FreeIPA session cookie;
- portal session cookie;
- XYOps API key;
- `ADMIN_TOKEN`;
- encryption/backup key;
- raw database;
- raw upstream response с внутренними данными.
