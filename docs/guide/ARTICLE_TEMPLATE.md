# Шаблон статьи базы знаний

Используйте этот шаблон для практических инструкций. Удаляйте разделы, которые явно не применимы; не заполняйте их предположениями.

## Для кого

Укажите роль или аудиторию: User/Viewer, Operator, Administrator, Operations/DevOps, Support, Developer.

## Что вы сможете сделать

Одним абзацем опишите результат, который получит читатель.

## Перед началом

- необходимые права или роль;
- предварительные условия;
- что должно быть настроено;
- что не требуется раскрывать или передавать.

## Пошагово

1. Откройте нужный раздел портала.
2. Выполните действие.
3. Проверьте показанный результат.

Пишите шаги по пользовательским действиям, а не по внутренним именам модулей.

## Что должно произойти

Опишите нормальный результат и безопасные признаки успеха. Не используйте внутренние секреты, raw responses или production-specific значения как доказательство.

## Если что-то пошло не так

Перечислите только подтверждённые типовые состояния и безопасный следующий шаг: повторить чтение, проверить права, открыть diagnostics, дождаться `Retry-After`, обратиться к администратору или поддержке.

Не советуйте отключать TLS, RBAC, origin/CSRF checks, approvals, validation или другие security controls ради обхода ошибки.

## Когда обращаться к администратору или поддержке

Укажите признаки, при которых пользователь не должен продолжать самостоятельно, и какие безопасные данные можно передать: время события, тип действия, correlation ID, безопасный error code.

Не запрашивайте пароли, session cookies, API keys, encryption keys или raw database.

## Связанные материалы

Ссылайтесь на актуальные guide-страницы и canonical engineering reference/runbooks. Не копируйте большие технические процедуры в эту статью.

## Проверка перед PR

- [ ] Инструкция соответствует current main, а не только issue/plan.
- [ ] Роль и prerequisites указаны.
- [ ] Будущая функция не описана как существующая.
- [ ] Нет credentials, cookies, keys, PII и internal production values.
- [ ] Security boundary не ослабляется советом «временно отключить проверку».
- [ ] Deep technical procedure ссылается на canonical owner.
- [ ] Internal links проверены.
- [ ] Knowledge Base impact связанной feature issue/PR учтён.
