# Поиск и пагинация пользователей FreeIPA

Раздел `/users` использует серверный query-контракт портала. Браузер получает только выбранную страницу нормализованных пользователей и не выполняет фильтрацию полного ответа самостоятельно.

## API

```text
GET /api/integrations/users
```

Без query-параметров endpoint сохраняет прежний формат ответа для совместимости с существующими CRUD-модалками и интеграционными тестами.

Для серверного поиска поддерживаются параметры:

| Параметр | Значения | По умолчанию |
|---|---|---|
| `q` | логин, ФИО, email или название группы | пусто |
| `status` | `all`, `active`, `disabled` | `all` |
| `group` | точное название группы | пусто |
| `sort` | `uid`, `name`, `email`, `groups`, `status` | `uid` |
| `direction` | `asc`, `desc` | `asc` |
| `page` | положительное число | `1` |
| `pageSize` | `10`, `25`, `50`, `100` | `25` |

Пример:

```text
/api/integrations/users?q=devops&status=active&group=devops&sort=name&direction=asc&page=1&pageSize=25
```

Ответ:

```json
{
  "mode": "live",
  "users": [],
  "pagination": {
    "page": 1,
    "pageSize": 25,
    "total": 0,
    "totalPages": 1,
    "from": 0,
    "to": 0
  },
  "filters": {
    "q": "devops",
    "status": "active",
    "group": "devops",
    "sort": "name",
    "direction": "asc",
    "page": 1,
    "pageSize": 25,
    "availableGroups": []
  },
  "summary": {
    "total": 0,
    "active": 0,
    "disabled": 0,
    "filtered": 0
  }
}
```

## Ограничения и безопасность

Параметры нормализуются на сервере:

- текстовые значения очищаются от управляющих символов;
- сортировка, состояние и направление принимаются только из белого списка;
- `pageSize` ограничен значениями `10`, `25`, `50`, `100`;
- номер страницы ограничен безопасным диапазоном;
- сортировка всегда имеет стабильный fallback по `uid`;
- пароли FreeIPA, session cookies и service account не возвращаются браузеру.

FreeIPA `user_find` в текущем контракте не используется как cursor/offset API. Поэтому портал выполняет один нормализованный `user_find` на запрос, затем применяет поиск, фильтры, сортировку и разбиение на страницы на серверной границе портала. Браузер получает только одну страницу, но это не является нативной offset-пагинацией FreeIPA.

## Интерфейс

Состояние таблицы сохраняется в URL страницы `/users`:

```text
uq       — поиск
ustatus  — состояние
ugroup   — группа
usort    — сортировка
udir     — направление
upage    — страница
usize    — размер страницы
```

Это позволяет обновить страницу или передать ссылку с теми же фильтрами.

CRUD не дублируется новым компонентом. Кнопки карточки, создания и редактирования вызывают существующие React-модалки, которые используют прежние server-side RBAC-проверки, FreeIPA actions и append-only аудит.

Для роли `viewer` доступны поиск, фильтрация и карточка пользователя. Кнопки создания и редактирования отображаются только при наличии `freeipa.write` в существующем интерфейсе.
