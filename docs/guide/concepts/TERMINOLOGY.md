# Термины базы знаний

Этот документ помогает писать инструкции одинаковым понятным языком. Он не заменяет канонический инженерный glossary: [`../../reference/GLOSSARY.md`](../../reference/GLOSSARY.md).

## Принципы

- Пользовательский термин объясняем простыми словами при первом употреблении.
- Technical identifier, route, permission code, process ID или error code не переводим так, чтобы изменился его смысл; визуально отделяем его от обычного текста.
- Не используем несколько разных русских названий для одного пользовательского понятия без причины.
- Не называем состояние «ошибкой портала», если фактически недоступна только внешняя интеграция.
- Не смешиваем локальную identity портала и identity FreeIPA.

## Базовые понятия

### Портал

**Admin Dashboard Softrust** — само приложение. Оно имеет собственные локальные учётные записи, роли, сессии, настройки и audit.

### Пользователь портала

Локальная учётная запись, используемая для входа в Admin Dashboard Softrust. Она не является автоматически пользователем FreeIPA.

### Пользователь FreeIPA

Объект каталога FreeIPA. Наличие такого объекта не означает наличие локальной учётной записи портала.

### Viewer

Роль с правами просмотра согласно текущему server-side permission contract. В пользовательском тексте можно писать «пользователь с правами просмотра», если техническое имя роли не требуется.

### Operator

Роль оператора. Конкретные разрешённые действия определяются текущим server-side permission contract, а не тем, какие кнопки видны в UI.

### Administrator / Admin

Администратор портала. Не используйте слово «администратор» без контекста там, где можно спутать администратора портала с FreeIPA administrator/service account.

### FreeIPA

Внешняя система каталога пользователей и групп. Портал обращается к ней через server-side integration boundary.

### XYOps

Внешняя система, которая владеет определением и фактическим исполнением automation processes/jobs. Портал не должен описываться как владелец очереди или scheduler XYOps.

### Process

Доступный в XYOps процесс автоматизации, который портал может показать или запустить в пределах разрешений и policy.

### Operation

Зафиксированное порталом действие или запуск с состоянием и результатом. Не используйте `operation` и `process` как полные синонимы.

### Approval

Согласование, необходимое для некоторых действий/процессов согласно действующей policy.

### Session

Серверная сессия входа в портал. Не показывайте и не просите прислать session cookie.

### Audit

Журнал значимых действий и результатов, предназначенный для контроля и расследования. Не обещайте наличие внешнего SIEM/export, пока соответствующая функция не реализована на current main.

### Diagnostics

Безопасная диагностика состояния портала и интеграций. Это не означает доступ к raw secrets, environment или upstream responses.

### Healthy

Компонент работает в пределах текущего health contract.

### Degraded

Портал или функция продолжает работать частично, но одна из зависимостей/возможностей недоступна или ограничена. Не переводите `degraded` как «портал полностью не работает».

### Unavailable

Запрошенная функция или зависимость сейчас недоступна. Это отличается от отсутствия данных и отсутствия прав.

### Forbidden / нет прав

Запрос отклонён из-за недостаточных разрешений. Не маскируйте это под «пустой список» или «сервис недоступен».

### Empty / нет данных

Запрос выполнен, но подходящих данных нет. Это не ошибка интеграции.

### Maintenance mode

Режим обслуживания, который ограничивает обычные изменения согласно current server-side contract. Точные процедуры включения/выключения берите из canonical operations documentation.

### Recovery / восстановление

Процедуры восстановления работоспособности или данных. Для destructive/offline действий используйте профильный canonical runbook, а не краткую статью Guide.

## Что не следует писать

Избегайте формулировок:

- «отключите проверку TLS, чтобы заработало»;
- «вставьте сюда реальный API key»;
- «пришлите cookie/пароль для диагностики»;
- «UI не показывает кнопку, значит действие запрещено сервером»;
- «FreeIPA user и portal user — одна учётная запись»;
- «XYOps queue управляется порталом».

Если термин или поведение не подтверждены current main/canonical docs, пометьте это как не подтверждённое и не превращайте предположение в инструкцию.
