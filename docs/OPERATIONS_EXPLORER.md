# Журнал операций и временная шкала

Раздел `/operations` использует существующий API журнала:

```http
GET /api/integrations/runs?limit=100&sync=0
```

Кнопка ручного обновления выполняет запрос с `sync=1`, поэтому портал сначала синхронизирует активные задания с XYOps, а затем показывает актуальный журнал.

Explorer и существующая таблица запрашивают одинаковые 100 последних операций. Благодаря этому любая строка, найденная фильтрами, открывается через прежнюю карточку `RunDetails`.

## Фильтры

Доступны:

- поиск по названию процесса, `eventId`, `jobId` и объекту операции;
- фильтр по точному статусу;
- объединённые статусы «Все активные» и «Все завершённые»;
- фильтр по инициатору;
- период по дате запуска;
- сортировка по времени запуска или продолжительности;
- пагинация на 10, 25, 50 или 100 строк.

Состояние фильтров сохраняется в query-параметрах страницы с префиксом `o` и не влияет на глобальный поиск каталога.

## Совместимость с существующими действиями

Новый интерфейс не вызывает `cancel` или `rerun` напрямую. При выборе строки он открывает прежнюю карточку `RunDetails` по `jobId`.

Таким образом сохраняются:

- существующая проверка RBAC;
- подтверждение опасного действия;
- safe re-run с проверкой `schemaVersion`;
- approval gate;
- redaction результатов и ошибок;
- существующие маршруты остановки и повторного запуска.

## Продолжительность

Для задания рассчитываются:

- общая продолжительность;
- время начала и завершения либо последнего обновления;
- продолжительность каждого этапа;
- ожидание между этапами;
- смещение начала этапа относительно запуска задания.

Для выполняющегося задания продолжительность обновляется каждую секунду. Если XYOps не вернул timestamps этапов, портал показывает общую продолжительность и явно сообщает, что детализация отсутствует.

## Ограничения

Фильтрация выполняется в браузере над полученным журналом. XYOps остаётся источником статусов и этапов, а портал не создаёт собственную модель очередей или исполнения.
